## 七、2026-09-27 新落地的两件事（写卡要知道的）

**1）伤害怎么算是两条管线，不是一条。** 攻方那条只管"这一发该报出去多少"（基础值 → 系统系数 → 全伤 → 武器分类 → 专属 buff → 特殊伤害 → 暴击 → 方向增伤 → 之后才加"只加本伤害源"和"追加结算"），算完把「数值 + 分类 + 穿透声明」交出去；守方那条再跑自己的账（免疫否决 → 护盾吃 → 固定减伤 → 比例减伤）。分成两条是因为主语不同：合成一条就会出现"守方的减伤被攻方的暴击又放大一次"这种账。

对内容侧的三条实际影响：

- **顺序不需要你们操心**，引擎写死了，卡面没有"优先级"可写；想改顺序要提出来走裁定。
- **"免疫"与"减伤到 0"是两件事。** 只有免疫能把一伤打成 0，而且要写清是谁免疫的；减免类单个来源写不到 100%（会直接报加载错误），要么走免疫，要么多个来源叠（永远到不了全免）。
- **护盾是点数**，会吃完，每个来源各吃各的（"坚壁仪式"每 30 秒攒一层那种），不吃白不吃，吃完就没了。

**2）卡面终于能写条件了，而且能写"或者"。** 之前只有"持有某标签"这一种判断；现在有 20 条判定条件 + 6 种组合方式（全部满足 / 任意一条 / 取反 / 若则否则 / n 条里 k 条 / 按顺序轮转），并且"未察觉"这种被当成了一个词的写法已经替你们展开好了（背后 120° 内／目标被吸引·被控制·失明／自己刚从视野外出现，任意一条即可）。具体键名和写法看《机制词表·已注册》第三节。

**还缺什么**：其余动作的执行器（`lethal_immunity` 之外那十三种现在只做解析与跨卡校验，不落世界）；能站在地上持续存在的东西（假身、陷阱链）——这两块等你们 Q7 的规则边界答复。

**2026-09-27 补：动作开始落地了。** 第一种是「免疫致命伤害」，走的是完整链路：判定条件说"这一发确实致命"→ 守方管线第①步把伤害打成 0 → 用掉的次数进冷却。它在游戏里验过三件事：不致命的挨打**不扣冷却**（不然真该救命那次就没了）、致命那一发被打成 0、冷却在途时第二次致命**要真的打死人**。规则与 `uses`/`cooldown` 的唯一读法写在《机制词表·已注册》第三节。

**2026-09-28 补：判定开始读真实世界了。** 入射角、距离、光照、血量线、是否致命、是否在动、是否蹲下——这些现在从真实命中里折出来，所以「背后 120°」这类条件不再只是纸面上能写。**直接后果**：`方向增伤` 变成了真条件乘区，正面一刀吃不到、背后一刀才吃得到（游戏里验过：同一张卡正面 10 点、背后 13 点）。原版没有现成来源的那几条（发声、"刚从视野外出现"、目标被吸引/被控制、精英与 boss 归类）**继续留白不猜**，写卡前请看《机制词表·已注册》第三节那张"现在真能判 / 还判不了"的分界。

**2026-09-28 补二：动作落到第二种了，事件也通了两个。** 现在在世界里真会响的是 `lethal_immunity` 与 `stacks`（攒层 / 扣层，受声明上限夹住），能被叫醒的事件是 `hit`（我打中的这一下）与 `damage_taken`（我挨的这一下）。游戏里验过一整圈：打中一下攒一层「扎根」→ 下一发挨打时那一层的 10% 减伤真的生效 → 连续命中涨到声明上限 3 层为止 → 它挨的打不算命中（不会顺手多攒一层）。**其余事件名（`parry_success`、`charge_release`、`kill`、`tick`…）解析与校验都通过，但目前没有代码发这些事件**，写在这些事件上的卡不会响——这是下一批的活，写卡前请先确认事件在不在"通了两个"里面。没有执行器的动作会往日志里报一条 warn，不会静默跳过。

**2026-09-28 补三：又落地两种，一共四种了。** `damage`（独立伤害＝基数 × 系数；基数只认护甲属性 / 攻击力 / 这一发的量 / 常数四种，写别的直接加载错误；`radius` 是以持卡人为圆心的半径格数）与 `knockback`（推开目标）。**独立伤害是"另一整发"**：它会完整再过一次两条管线（攻方乘区照乘、守方减免照算——这正是《00》"以护甲值为基数的完整乘区"要的），但不并进原来那一发的数，所以同一个乘区不会对同一个数字生效两遍。游戏里验过：半径内的邻居确实掉了血、也确实被推动了，而它从没被直接攻击过；邻居掉的血小于 2 点，证明"独立伤害触发命中、命中再触发独立伤害"那条递归被拦住了（拦不住就不是断言变红，而是整条测试栈溢出）。
**顺带验实的一条原版行为**：独立伤害遵守原版无敌帧，所以冲击波对**刚被那一刀砍中的目标**不叠加，只对旁边的目标生效（实测直接目标只掉了"5 点经护甲削减"那一发）。要改成叠加是玩法决定——技术上就是给这个伤害类型挂 `BYPASSES_COOLDOWN` 标签——**你们说一声我们再动**；现在按原版行为实现，并已有测试把这个现状钉住。

**2026-09-28 补四：盾反的时机真的在游戏里判了。** 举盾挡下一发时，引擎按"举盾已经举了多少 tick"落在窗口内/外来发 `parry_success` 或 `block_success`（窗口由招式卡声明的 `base_window` × 延长/乘区/难度折出来，公式只有求解器那一份）。游戏里验过：窗口内挡下 → 攒一层壁障；举久了出窗 → 只算普通格挡、不攒层。三道闸门写进《机制词表》第三节，其中一条值得单说：**原版要求举盾满 5 tick 才算在挡**，所以"窗口 0.1 秒"那种写法是结构上永远打不出来的死区，不是配置项。

**一处需要你们定的玩法问题（我们没擅自改）**：现在玩家举盾挡下近战时，**原版是把这发伤害整个取消**的，于是卡面里的"格挡减伤 20%""精准格挡奖励"这类数值对伤害本身不起作用（事件与奖励照发，伤害那一段还是原版行为）。要改成"格挡只按比例减伤、不再全挡"技术上已经现成——我们就挂在原版的格挡事件上，那里可以直接改"挡住多少"——**剩下的纯粹是玩法裁定**，会影响所有盾线手感：① 保持原版全挡，格挡数值只作为条件与奖励存在；② 改成按 `block.reduction` 比例减伤（盾反窗口内可另算倍率）；③ 保持全挡、但让穿盾类伤害走比例。我们倾向 ②（卡表里"格挡减伤"这栏在 ① 下没有意义），但这不是我们能替你们定的，等一句裁定。



**2026-09-28 补五：覆盖表排第一的那半修掉了。** 卡表"附带数值"那一整列（`+20 护甲值`、`+15% 移速`、`+20% 生命上限`、`+8 攻击速度`）之前**折得进快照但没人往玩家身上挂**，所以整列是空话——现在这四条通道真的投影到原版属性上了（稳定 UUID、幂等、点值/比值不混、上限降下来当场夹血，游戏里断言过 +10 护甲与 ×1.2 移速、重算两遍不叠加、卡清空后摘干净）。同时多落地两种动作：`reflect`（把这发的比例还给打我的那位）与 `force_parry`（N 秒内格挡一律按精准，且照发 `parry_success`，否则那条动作等于没做）。**顺带钉住一件时序**：举盾挡下的那发被原版整个取消，所以走不到伤害事件——想"挨打拿窗口"必须先真的结结实实被打中一次，这条已写进 GameTest。
**还缺落点的通道**（写了不报错、但今天什么都不产生）：`crit_chance`、`crit_damage`、`physical_damage`、`base_damage`、`armor_pierce`、`lifesteal`、`resistance`。要它们生效就得先把**格挡到底减多少**（上面那条裁定）和**暴击怎么算**一起定下来，否则我们只会做出第二套真相。

**2026-09-28 补六：周期真的在跑。** 卡面写 `{"type":"trigger","on":"tick","every":30.0,…}` 就会每 30 秒兑现一次——之前 `every` 的解析、校验、秒→tick 换算全在，只差那个把玩家过一遍的调用点，所以"每 30 秒获得一层护盾"这类卡写了也不响。三条读法钉死：起算点＝引擎第一次看见这张卡的那一 tick（重启世界重新起算）；**错过的那些不追补**（服务器卡 3 秒不会把一次触发变三次）；同 tick 多个周期按卡 id 顺序跑、没到点的不会被顺带叫醒。游戏里断言了五步：起算那 tick 不触发、39 tick 不触发、40 tick 触发一次、79 tick 不追加、80 tick 第二次。
**2026-09-28 补七：攻方那三条事件通了，顺带揪出两处"写得出来但不响"的静默。** `attack`（出手）、`damage_dealt`（真的造成了伤害）、`kill`（打死）现在都在世界里发得出。三条的分工必须先读再写卡：`attack` 挂在原版 `AttackEntityEvent` 上，它由 `Player#attack` 的**第一行**发出，所以一刀哪怕被无敌帧吃掉、哪怕被对面免疫成 0，"出手"照样记；`damage_dealt` 只在这一发结算完真的不为 0 时发，而且**基数装的是结算后的最终值**（`hit` 的基数是进管线的那个数）；`kill` 只能挂 `LivingDeathEvent`——1.20.1 的 Forge **没有** `LivingDiedEvent` 这个类（源码核过），而它是可取消的，别的模组若取消这次死亡，我们的 `kill` 已经响过一次（这条偏差认了，不做假准的修补）。`attack` 与 `kill` 上没有"这一发的量"，也没有"打我的那位"，所以 `basis: incoming` 与 `reflect` 在这两条事件上天然没有对象；半径 0 的动作在没有对面的事件上过去会**直接把服务器打抛**（`List.of(null)`），现在改成报一条 + 跳过。

同批修的两处静默都属于"词表解析通过、条件也注册了，但世界侧没人取值"这一类，表现和"这张卡没用"一模一样：

- **`target_kind` 判的是持卡人自己**，不是对面那位。于是玩家持卡时它恒为 `player`："只打普通敌人"那类卡永远不响，"对玩家生效"那类永远响——后者是**会错触发**的方向，比不响更糟。现在取对面，且 `GameTest killingANormalTargetChainsOntoANeighbour` 钉住（把修复改回取自己，那条立刻红）。
- **`stacks`（层数）条件没有出处**：判定读的是事实快照，而快照里没人贴层数，所以"叠满 3 层才怎样"在世界里恒不成立。现在执行器在叫醒触发器之前把 `CounterStore` 的账贴进快照（`Facts.withLedger`，引擎自有的 `trigger.*` 资源不算叠层）。断言分两头：纯逻辑那条钉"贴"的形状，世界那条 `stackGatedConditionsReadTheLiveLayerCount` 连挥三刀——一、两层时不额外补伤害；二、第三刀补了；三、层数按刀涨（把贴账那一步去掉，第三刀就与第二刀一样，立刻红）。

**同一批里查出来、当时还没修的静默只剩一处**：`count`（本局累计次数）与轮转组合子 `sequence` 的指针共用同一个入口（`Facts.count`），今天也没有出处——纯逻辑两头都钉死了，缺的是引擎侧那本累计账。**这条同日已经补上了，见下面的补八。**

**2026-09-28 补八：`count` 与轮转指针真的有账了。** 执行器（`Triggers.fire`）现在在评测之前做三件事：① 把这一次的事件计数加进账本（键 `trigger.count.<事件名>`，无上限、不过期）；② 按条件树<em>点名</em>的资源把那几笔贴进事实快照（`Facts.withLedger`，只读被点到的键、不整本抄账本——账本会随一局游戏一直长，而一张卡的树只有几个节点）；③ 整条 `when` 成立之后把这张卡上的轮转指针各推进一格（`trigger.cursor.<id>`）。三条口径写卡前必须认：

- **`at_least: 3` 从第三次派动开始成立**，不是等到第四次——计数含这一次。反过来"先判后加"会整体晚一格，而且方向是"该响没响"，玩家只会以为这张卡没用（这条被断言钉住，把顺序写反立刻红）。
- **"本局"＝服务端进程里这本账活着的时候**，与世界重启同步清零、**不写存档**（与周期起点 `CardCadence` 同一口径）。要"跨重启仍累计"是一次新需求（要做持久化），不是现在改个开关就有。
- **指针只在整条门槛成立时推进**，过不去就停在同一步，转满一轮取模回到第 1 步。卡表里目前没有任何卡用 `sequence`，所以这条按唯一自洽的读法定了；若内容侧其实想要"每次派动都推进"，说一声再改。

顺带把 `count.on` 改成**必须引用已注册事件**的加载校验：写一个不存在的事件名，过去的表现是"这张卡永远不响"，现在直接是加载错误。另外"还剩几次可用"那个调试读数（`Triggers.inFlight`）明确排除计数与指针两族键——它们本来就永不过期，混进去会让一个 1 次充能的免疫卡显示成几百。

**2026-09-29 补九：`still_seconds` 有出处了，顺带把 `moving` 重写成同源的一条。** 之前 `moving` 由**速度**算、而"连续静止多久"根本没人算（快照里那一格永远是 0），所以 `{"still_seconds": 2}` 这类"站定才怎样"在世界里恒不成立；更糟的是两者不同源会出现自相矛盾的瞬间（坠落时速度非 0 但位置一直在变、站着被推时速度归零但位置在漂）。现在只有一份事实：**每 tick 末尾对位置采一帧**，"动"= 位置越过阈值，时长从最后一次越界起算，`moving` 与 `still_seconds` 都从这同一份采样里读（纯算法在 `core/effect/Stillness`，可无头断言；世界侧 `common/player/PlayerStillness` 只负责喂坐标和按 UUID 存）。

四条口径写卡前要认：

1. **"在动"的定义是位置变了**，不是速度非零——坠落、被推、顺水漂都算在动。因此 `{"moving": false}`（"站定"）比过去更严格，也更符合直觉。
2. **阈值是平方距离 1e-6 格²**（≈每 tick 0.001 格）。采样**保留旧锚点**，所以每 tick 只挪一点点的漂移会在约 1100 tick 后累计越界、判成"动了"。逐 tick 刷新坐标的写法会被漂移永久骗成站定——这条有专门的断言（把它改回逐 tick 刷新，门立刻红）。
3. **第一次看见一个人 = 静止 0 秒 + 没在动**：读操作不写状态，没采过样就是"无从谈起"，默认值只会让卡不触发。
4. **动了之后"在动"读数保持一整个 tick**：采样把锚点搬到新坐标之后若只比坐标，同一 tick 里稍后才到的那次命中会读成"没动"，`{"moving": true}` 那类卡会整 tick 漏触发（这条也是先写断言、再改实现验红的）。

**还差的**：`stand_still` <b>事件</b>现在数据都已经有了，只差"什么时候算站定"那一句阈值口径（例如"从动到静的那一刻响一次"）——这是玩法决定，等内容侧给话。示例卡「凤凰吐息」加了一条 `on: hit, when: [{still_seconds: 1.0}]` 的「蓄燃」层（每层 +6% 近战增伤），世界内 GameTest `stillnessIsMeasuredFromRealMovement` 分三段验：没采过样不涨、站着等够 25 tick 才涨、挪开三个方块之后不涨。

**当前能力盘点（逐张核对过的范围）**：两份三级池 + 入场券/前提共 **45 张**（54 行，重武的 18 张在两张表里各出现一次）——**5 张整卡今天能写**（表里 8 行 ✅，去掉重复后是弹反池 4 张 + 入场券「举盾而立」1 张）、18 行"语汇够但缺执行器/事件"、26 行缺槽位、1 张（子弹时间那种全局时间缩放）不该由引擎表达。**这 4 张弹反池的卡要特别说明**：它们当初被记为"能写"，前提是"`+10 护甲`、`+15% 移速` 这类附带数值能落到属性上"——那件事其实是今天才真的做出来的（见补五），所以这 4 张从前是**假绿**、现在才是真生效。419 张方式卡里其余约 365 张**还没逐张核对**，别把上面的比例当成全局结论。**补七没有把这张名单往前推**：`kill`／`attack`／`damage_dealt` 派发了，但用到它们的每一行各自还有别的缺项（蓄力进度回滚、"免费反击"的产出动作、负面效果施加），所以"今天整卡能写"仍是 5 张；真正往前走的是"部分能写"那 18 行——以及所有用层数当门槛的卡（`stacks` 条件现在有出处了）。
