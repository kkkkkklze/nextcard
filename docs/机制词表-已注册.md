## 一、核心设计：合成方式属于槽位，不属于卡面

这是本次注册唯一重要的架构决定。规格 §5.4 的"修饰槽位"落成后，**每个槽位自己声明
多张卡改写它时怎么合并**，卡面只有一个数值，写不出第二种解释：

| 合成方式 | 含义 | 用在 |
| --- | --- | --- |
| `SET` | 覆盖；两处给不同的值 = **加载期报错**（矛盾必须显式解决） | 语义唯一的开关（能否取消蓄力、窗口基础值） |
| `ADD` | 加算 | 窗口延长项、蓄力速度、各数值通道 |
| `MULTIPLY` | 乘算 | 乘区 |
| `DIVIDE` | 除法项 | 判定难度（÷3、÷2） |
| `MAX` | 取最宽松 | 上限类（层数上限、减伤上限、蓄力条上限） |
| `UNCAPPED` | 解除上限（布尔式，无值） | "不再有上限"类卡 |

因此卡表里那些**互相矛盾的写法**在结构上被消解了：

| 卡表原话 | 语汇里的答案 |
| --- | --- |
| 节奏记忆"不可单独叠加，如有【时机感知】则乘法叠加" vs 池说明"延长项走加法" | 延长项用 `window.length`（`ADD`）**只能加算**；要乘法必须改用 `window.scale`（`MULTIPLY`）这个独立槽位。**这一条需要你拍板**：若坚持乘算，该卡改写 `window.scale` |
| 壁障上限"3 层"→"最多 10 层"→"上限解除" | 声明给基准（3），改写走 `MAX`（10），解除走 `uncapped`（事实而非大数字） |
| 蓄力条"每张招式卡给出上限"+"开山 +2 秒" | `charge.bar_max` 声明 `MAX`（取最高）、`charge.bar_bonus` 声明 `ADD`（加算），两条链天然并存 |
| 战意每层蓄力速度 "+3%"（池说明） vs "+20%"（器灵苏醒） | 都是 `charge.rate` 的 `ADD` 来源 → 合成 +23%。**这一条也需要你拍板**（若为"替代"关系，得改成不同的槽位） |
| "减伤不再有上限"与"减伤翻倍"同时在场 | 分别落在 `block.reduction_cap`（`MAX` + 解除）与 `block.reduction_scale`（`MULTIPLY`），互不覆盖 |

## 二、槽位词表

### 事件（`trigger.on`，只能被监听）

`attack` · `hit` · `kill` · `tick` · `damage_taken` · `damage_dealt` · `block_success` ·
`parry_success` · `parry_fail` · `charge_release` · `charge_interrupt` · `control_immune` ·
`shield_down` · `stand_still` · `skill_cast`

### 参数（`mechanic_modifier.target`）

| 槽位 | 合成 | 用途（卡表来源） |
| --- | --- | --- |
| `window.base` / `window.length` / `window.scale` / `window.difficulty` | `SET` / `ADD` / `MULTIPLY` / `DIVIDE` | 精准格挡判定窗口（时机感知、节奏记忆、绝境读秒、反射神经、忘我之境） |
| `block.angle` | `MAX` | 格挡角度档，值写字符串：`front` < `front_side` < `all`（举盾习惯 / 全向盾墙 / 盾之誓约；两张卡各写一档时取最宽松） |
| `block.reduction` / `block.reduction_scale` / `block.reduction_cap` | `ADD` / `MULTIPLY` / `MAX` | 格挡减伤与其上限（稳手 20%、不动如山翻倍、盾之誓约解除） |
| `parry.reward_cap` | `MAX` | 弹反誓约"奖励不再有上限" |
| `charge.bar_max` / `charge.bar_bonus` | `MAX` / `ADD` | 蓄力条上限（招式卡 + 开山 +2 秒） |
| `charge.rate` | `ADD` | 蓄力速度（沉肩站定 +30%、战意每层） |
| `charge.resolve` / `charge.resolve_cap` | `ADD` / `MAX` | 本次蓄力的最终倍率及其上限（借力、稳桩、器灵苏醒） |
| `charge.damage_taken` / `charge.control_duration` | `ADD` | 蓄力期间受伤 +25%、受控时长 −30% |
| `charge.cancelable` / `charge.interruptible` | `SET` | 势不可回（不可取消）/ 蓄势不泄（不再被打断） |
| `stack.<叠层 id>.cap` / `.duration` | `MAX` | 任何叠层资源的上限与时长 |
| `stack.<叠层 id>.gain` | `ADD` | 产出修正 |
| `channel.<通道>` | `ADD` | 附带数值（见下） |

### 数值通道（附带数值的落点）

`armor` `max_health` `max_health_scale` `move_speed` `attack_speed` `crit_chance` `crit_damage`
`all_damage` `physical_damage` `melee_damage` `base_damage` `direction_bonus` `armor_pierce`
`lifesteal` `resistance` `damage_reduction`

- **点值通道**（卡面写 "+10 护甲值"）：`armor` `max_health` `base_damage`
- **能直接落成原版 AttributeModifier 的**：`armor` `max_health` `move_speed` `attack_speed`；
  其余进自定义伤害管线（M2），因为原版没有暴击、没有近战增伤、没有护甲穿透
- **独立相乘桶**（卡面写"额外乘区"）：`max_health_scale`——桶内仍加算，桶本身与主桶相乘
- 通道值恒为**增量**（`+15%` 写 `0.15`），不是乘数

### 叠层参数（`stack.<id>.<参数>` 的第三段）

`cap` · `duration` · `gain`。`<id>` 由内容声明，引擎只校验参数名合法；
**引用一个没人声明过的叠层 = 加载错误**。

## 三、条件与动作

条件是四种形态共用一个结构：数值（`{"hp_below": 0.3}`）、枚举（`{"angle": "front"}`）、
开关（`{"charge_active": true}`）、引用（`{"stacks": {"id": "barrier", "at_least": 3}}`）。

已注册条件键：`hp_below` `hp_above` `still_seconds` `charge_seconds` `angle` `target_state`
`moving` `blocking` `charge_active` `parry` `stacks` `count`

已注册动作（结构校验严格，语义在 M2 执行）：

`stacks`（加/减层数，可 `ignore_cap`）· `damage`（`basis`: armor/attack/incoming/const + 系数 + 半径）·
`knockback` · `stun` · `launch`（落地追伤比例）· `slow` · `reflect` · `extra_resolve`（可 `unbounded`）·
`copy_attack` · `crit`（必定暴击 / 暴击率与暴伤）· `lethal_immunity` · `force_parry`（一律按精准结算）·
`ignore_armor` · `interrupt`

## 四、两个池怎么落到语汇上（示例）

### 盾反：时机感知（窗口 +30%）+ 壁障（层数资源）

```json
{
  "tier": 1, "card_class": "B", "tags": ["nextcard:block"],
  "effects": [
    { "type": "mechanic", "id": "parry", "base_window": 0.4, "ordinary_reduction": 0.2 },
    { "type": "mechanic_modifier", "target": "window.length", "value": 0.3 },
    { "type": "mechanic_modifier", "target": "channel.move_speed", "value": 0.10 },
    { "type": "stacks", "id": "barrier", "scope": "persistent", "cap": 3, "duration": 6.0,
      "gain": [ { "on": "block_success", "amount": 1 } ],
      "per_stack": [ { "target": "channel.damage_reduction", "value": 0.03 },
                     { "target": "channel.damage_reduction", "value": 0.04,
                       "when": [ { "angle": "front" } ] } ] }
  ]
}
```

窗口算法（`WindowMath`）：
`窗口 = 基础 ×（1 + Σ延长项）× Π乘区 ÷ Π难度`
→ 时机感知 + 节奏记忆 + 绝境读秒 + 反射神经 = `0.4 × (1+0.3+0.5) × 2 ÷ 3`。

角度档（`block.angle`）与"格挡不再受角度限制"共用同一槽位，只是取最宽档：

```json
{ "type": "mechanic_modifier", "target": "block.angle", "value": "all" }
```

### 蓄力：招式卡（给上限）与辅助卡（改规则）

```json
// 招式卡（过肩劈）：声明并授予机制 + 自己的蓄力点
{ "type": "mechanic", "id": "charge", "bar_max": 2.0 },
{ "type": "trigger", "on": "charge_release", "at": 2.0,
  "actions": [ { "crit": { "chance": 0.2 } }, { "stun": { "seconds": 1.5 } } ] },
{ "type": "mechanic_modifier", "target": "channel.melee_damage", "value": 0.10 }

// 辅助卡（沉肩）：只改规则，不提供蓄力条
{ "type": "mechanic_modifier", "target": "charge.rate", "value": 0.30 }

// 辅助卡（开山）：+2 秒上限 + 5 秒档的招式
{ "type": "mechanic_modifier", "target": "charge.bar_bonus", "value": 2.0 },
{ "type": "trigger", "on": "charge_release", "at": 5.0,
  "actions": [ { "ignore_armor": { "ratio": 0.5 } }, { "knockback": { "strength": 1.0, "radius": 4 } } ] }
```

蓄力表（`ChargeTable`）：上限 = 声明值取最高 + 加成加算（3 + 2 = 5 秒）；
时刻 t 生效的招式 = "`at` ≤ t 的最高档"（同档多张卡一起触发），声明 `inherits` 的档把下面一档一并带出
（3 秒档"保留 2 秒那一档的加成"）；超过上限的部分每段转 1 层「过量蓄势」。

## 五、加载期会硬报错的情况（fail-fast，绝无静默）

1. 未知子句类型 / 未知事件 / 未知槽位 / 未知机制 / 未知动作 / 未知条件
2. 子句、动作、条件里出现当前类型不认识的键（带上下文，如 `action stun: unknown key meters`）
3. 改写一个**没有卡声明过**的机制（`charge.*` 无 `mechanic: charge`）
4. 引用一个**不存在**的叠层（`stack.ghost.cap`、动作 `stacks.id`、条件 `stacks.id`、每层来源 `counter`）
5. 同一个叠层被声明成两种 `scope`；语义唯一的槽位出现两个不同值
6. 在非上限类槽位上写 `uncapped`；同时写 `value` 与 `uncapped`；枚举槽位（`block.angle`）写数字或写错档位
7. 叠层 id 不合规范（须匹配 `[a-z0-9_.-]+`）；`at` 绑在非 `charge_release` 事件上

## 七、内容作者注意事项（会踩的坑）

1. **不要用引擎槽位名当卡文件名**。门 G2 会把每张卡的**文件名**当作内容字面量去扫 `core/`——
   若出现 `cards/charge.json`，`core/Mechanics.java` 里的 `"charge"` 就会被判违规。
   槽位名与机制名（`charge`、`parry`、`barrier`……）属于引擎，卡文件名请避开它们。
2. 槽位 id 用**点号**分隔（`window.length`、`stack.barrier.cap`、`channel.armor`），不要用冒号：
   冒号形式的值会被 G2 当成内容 token 收集。
3. 每张卡仍须满足既有的加载校验：tier 1–5、A 类 tier≥3 且声明体系、C 类 tier≥5、
   标签已注册、`requires` 是可解析的标签、每卡至少一个非判断标签。
4. 改完内容跑 `./gradlew logicTest`：G1（空内容可调用）/ G2（core 无内容字面量）/
   G3（概率性质）/ 内容一致性 / 本词表门，共 26 个用例。
5. 本机构建需要 Java 21 工具链（MDG 要求），当前用 Trae 自带的 Temurin 21：
   `./gradlew logicTest -Porg.gradle.java.installations.paths="<jdk21 路径>,<jdk17 路径>"`
